# 数据与接口契约

版本 V0.4。字段的机器定义见 [核心 Schema](contracts/核心对象.schema.json)，HTTP 定义见 [OpenAPI 3.1](contracts/openapi.json)。本文解释跨对象约束、默认值、存储索引、幂等与事件语义；实现不得只参考画板猜字段。

## 1. 通用约定

- 所有时间以 UTC ISO 8601 保存，界面按 Asia/Shanghai 显示；法律日期用 YYYY-MM-DD，不把它转换成抓取时间。
- 业务 ID 为 UUID 字符串；version_id/chunk_id 为 SHA256 十六进制，evidence_id 只在 query 内使用 E1、E2 等编号。
- MongoDB 中 _id 与契约主键同值；HTTP 隐藏 _id，不暴露内部文件路径、凭据和堆栈。
- nullable 必须返回 null，不用空字符串或“无”替代。枚举小写 snake_case，中文仅用于展示。
- JSON 对象默认禁止未知字段；请求缺省值由服务填充，不能依赖前端校验。列表 limit 默认 20、最大 100，按 created_at、主键稳定排序；next_cursor 为不透明游标。
- 单工作空间标识 default，由后端填充；首期不接受客户端任意 workspace_id。session 附件只允许当前会话访问。
- 日期约束 effective_to > effective_from；start_char ≤ end_char；有效页码≥1；有限数值与维度在入库时检查。

## 2. ID 与身份规则

| 标识 | 生成方式 | 使用范围 |
| --- | --- | --- |
| document_id | UUID | 稳定资料身份；同名文件不是同一身份的充分条件 |
| version_id | SHA256(document_id＋文件摘要＋pipeline_revision) | 不可变导入版本，解析器/切片策略变化也生成新版本 |
| chunk_id | SHA256(version_id＋ordinal＋正文摘要) | MongoDB、Milvus、Neo4j 共用 |
| entity_id | SHA256(entity_type＋规范身份键＋必要的 version_id) | 条款与参与查询的 Case 实例均含资料版本；Case.case_identity_key 用案号/稳定来源标识归并同案身份 |
| query_id/message_id/task_id | UUID | 一次查询、消息、执行任务 |
| source_id | 本地为 chunk_id；外网为 web:SHA256(规范 URL＋正文摘要) | 候选去重；不同版本不合并 |
| evidence_id | 按当前轮最终证据排序编号 | 与 query_id 复合唯一，不能跨轮直接打开 E1 |
| 模型部署标识 | served_model_name＋产物 SHA256 | 来自程序外部署清单，仅记录回答模型出处，不提供训练/实验资源 API |

同内容重复上传：未指定替换目标时，同 scope、session_id（若有）、文件摘要及 pipeline_revision 返回默认内容登记的资源；指定 replace_document_id 时，先验证目标可见性，再只查该 document_id 内的同摘要版本。即使 B 已有相同文件，也必须为 A 保持自身 document_id/version_id，可共享原件对象但不能返回 B 的版本。

上传 request_id 相同但文件摘要或任意身份参数（含 replace_document_id）不同返回 409 IDEMPOTENCY_CONFLICT。新版本发布前旧版本保持可见。并发默认上传通过 content_registry 的唯一登记键分配固定资源 ID，登记中断时按已分配 ID 恢复，不重复创建；显式替换走 document_id 内的唯一版本键，不改写默认登记指向。

## 3. MongoDB 数据集合

核心 Schema 是业务视图，租约、成本预留等内部字段在下表补充。所有集合含 schema_revision=0.4、created_at、updated_at（只读不可变记录可无 updated_at）。

| 集合 | 主体字段及类型 | 索引与约束 |
| --- | --- | --- |
| documents | Document；workspace_id=default | document_id 唯一；scope,session_id,tombstoned,updated_at 组合查询 |
| document_versions | Version（含 pipeline_revision、published_at）；stage_artifacts:object 为内部恢复字段 | version_id 唯一；document_id,sha256,pipeline_revision 唯一；允许不同 document_id 使用相同内容 |
| content_registry | scope、session_id、sha256、pipeline_revision、document_id、version_id、task_id、creation_state | scope,session_id,sha256,pipeline_revision 唯一；仅默认上传身份登记，显式替换不更改它 |
| chunks | Chunk；workspace_id、scope、session_id、content_sha256、parser_revision | chunk_id 唯一；version_id,ordinal 唯一；正文权威来源 |
| import_tasks | TaskStatus；request_id、input_hash、stage_success[]、lease_token、lease_until、heartbeat_at、cancel_requested | task_id 唯一；scope/request_id 唯一；status,lease_until,created_at 领取任务 |
| sessions | Session；workspace_id、last_query_id | session_id 唯一；deleted,updated_at |
| messages | message_id、query_id、session_id、role、content、status、facts、created_at；来自 queries 的可重建投影 | query_id,role 唯一；session_id,created_at,message_id |
| queries | QueryStatus；request_id、input_hash、request、snapshot_version_ids[]、facts、path_status、cancel_requested、lease_token、lease_until、revision、event_log[]、events_expires_at、events_expired | session_id,request_id 唯一；query_id 唯一；status,created_at；答案、证据快照和事件在同一文档原子更新 |
| graph_unresolved | citation_id、source_chunk_id、raw_text、cited_title、article、reason、extractor_revision | source_chunk_id,引用摘要 唯一；不形成 CITES 边 |
| cost_ledger | entry_id、kind、model、pricing_revision、reserved/estimated/settled、usage、amount_yuan、external_receipt_id | entry_id 唯一；外部账单标识去重 |
| budget_account | id=project、limit、settled、reserved、estimated_unsettled、pricing_revision、reservations:request_id→金额/状态 | 单文档原子预算闸门，同 request_id 不重复预留/结算；ledger 是可补写对账投影 |
| idempotency | scope、request_id、input_hash、resource_id、creation_response | scope,request_id 唯一；首期保留整个演示期 |

知识删除为 tombstone，不在 HTTP 请求中直接遍历三库递归删数据。后台 cleanup 记录处理进度；会话删除同样先关闭可见性，标记未完成 query 取消，私有附件随该会话撤销。

queries 保存请求原文、已提交答案与终态，是会话轮次的权威记录；messages 是按 query_id,role 幂等写入的展示投影。终态已提交而消息投影尚未写入时，历史接口从 queries 回补并由维护任务重建，不重复生成答案或让完整轮次消失。用户消息同样从已接受 query 的 request 恢复。

预算的 reservations 内保存请求的预留/结算状态，CAS 同时更新对应金额和总计；重复请求不再扣减。cost_ledger 写入中断后从 reservations 与供应商 usage 恢复，不再次预留。首期最多 10000 条计费请求登记，达到限额先对账归档已结算项并保留幂等摘要，不能无限增长到 MongoDB 文档容量上限。

## 4. Milvus 集合

集合名 legal_chunks_v1；模型切换建新集合，不覆写原维度。字段：chunk_id VARCHAR(64) 主键非 auto_id；version_id/document_id VARCHAR；workspace_id/scope/session_id；doc_type；scenario_tags；dense FLOAT_VECTOR(dim=1024)；sparse SPARSE_FLOAT_VECTOR。

主显示正文读取 MongoDB，Milvus 不承担唯一正文副本。dense 使用 COSINE、sparse 使用 IP；第一阶段分别建立可用索引（默认 AUTOINDEX 与 SPARSE_INVERTED_INDEX，须对所锁定版本实测）。检索必须带 snapshot_version_ids 和 scope/session 限制，不能先跨全部会话召回再在页面过滤。

如果部署版本不支持所需稀疏索引，预检失败并修正部署，不得把 dense-only 伪装成混合检索。测试替身只在 MOCK 模式下使用，演示报告显示真实/模拟运行模式。

## 5. Neo4j 图模型与查询模板

节点唯一键：LegalDocument.document_id、DocumentVersion.version_id、Provision.entity_id、Case.entity_id、Issue.entity_id、Organization.entity_id、EvidenceChunk.chunk_id、RelationEvidence.assertion_id。Case 是版本化实例：entity_id=SHA256(case_identity_key＋version_id)，另存稳定 case_identity_key 用于同案分组；不可按案号复用一个节点并覆盖其 version_id。引用边及 RelationEvidence 绑定来源案例版本与目标条款版本。

关系事实以 RelationEvidence 保存方法、状态、来源位置、原文短引和证据切片，关联端点与证据；业务边保存 assertion_id 便于反查。避免试图把“关系边”当可直接连接其他关系的节点。SUPERSEDES 只接受原文明确替代信息；自动抽取不能仅凭日期建立替代。

关键关系：HAS_VERSION、HAS_PROVISION、CITES、CONCERNS、ISSUED_BY、SUPERSEDES、SUPPORTED_BY。来源正文存在且短引匹配的标为 source_supported；引用版本有歧义标 unresolved，写 graph_unresolved 而非确定 CITES。

模板目录：

| 模板 ID | 输入 | 方向和结果 |
| --- | --- | --- |
| provision_lookup | 已消歧法规版本＋article | Version→Provision→EvidenceChunk；取原条款 |
| issue_cases | issue_id | Issue←CONCERNS—Case→EvidenceChunk；返回案例证据 |
| case_provisions | case_id | Case—CITES→Provision→EvidenceChunk；返回条款及引用的来源 |
| version_provisions | version_id | Version—HAS_PROVISION→Provision；仅筛选版本内条款 |

示意模板遵循参数化查询（最终字段与上述模型一致）：

```cypher
MATCH (c:Case {entity_id: $case_id})-[r:CITES]->(p:Provision)
MATCH (a:RelationEvidence {assertion_id: r.assertion_id})-[:SUPPORTED_BY]->(e:EvidenceChunk)
WHERE a.status = 'source_supported'
  AND c.version_id IN $visible_version_ids
  AND p.version_id IN $visible_version_ids
  AND e.version_id IN $visible_version_ids
RETURN c.entity_id AS case_id, p.entity_id AS provision_id,
       a.assertion_id AS assertion_id, e.chunk_id AS support_chunk_id
ORDER BY assertion_id
LIMIT $limit
```

模板参数只允许固定字段/类型；关系类型和跳数来自服务端白名单，不通过字符串拼接用户输入。单独查询最终条款原文作为证据时，还必须回取其自身 SUPPORTED_BY 切片；案例引用文字与条款正文不是同一个证据。

## 6. 任务与查询状态机

### 6.1 导入

queued→running→succeeded / succeeded_with_warnings / failed / cancelled。

stage 从 validate 到 publish 单向推进，成功写 done；重试 failed→queued，attempt 递增并复用已校验阶段。出现警告不进入人工审核；向量可用但图失败/元数据缺失时发布 limited 并 succeeded_with_warnings。

业务 availability 与任务状态独立：failed 的新版本不影响旧已发布版本；succeeded 表示管道成功，不表示法律判断经过审核。

### 6.2 查询

queued→running→completed / completed_with_warnings / failed / interrupted / cancelled。

behavior=clarify、insufficient 可以是正常 completed；它们不是系统错误。生成中断为 interrupted，并保存 partial 消息。只有业务必要输出已经持久化后，才能写 done/完成状态。

QueryStatus 同时返回 generation_model_id、generation_artifact_sha256：实际调用回答模型时记录服务 ID 和核对过的部署清单产物摘要，尚未调用时为 null。摘要来自可信部署清单和服务启动核对，不能仅根据模型返回的同名字符串推断权重身份。对 answer 终态必须能追踪本次生成客户端；模板化 clarify/insufficient 不谎称已调用模型。

## 7. HTTP 通用响应与错误

成功返回 OpenAPI 中的资源对象或 items,next_cursor；错误返回：

```json
{"error":{"code":"DOCUMENT_NOT_READY","message":"资料尚未完成向量索引","request_id":"9bb41eba-55cf-4d22-b639-c4b7a5656faf","retryable":true,"details":{"vector_state":"running"}}}
```

| HTTP | 稳定错误码示例 | 行为 |
| --- | --- | --- |
| 400 | INVALID_FILE_TYPE、INVALID_DATE_RANGE、PARSER_UNSUPPORTED | 修改输入或使用支持格式，不自动重试 |
| 404 | RESOURCE_NOT_FOUND、EVIDENCE_NOT_FOUND | 不泄露其他会话或私有文件存在性 |
| 409 | IDEMPOTENCY_CONFLICT、INVALID_STATE、ATTACHMENT_NOT_READY | 同请求不同内容、错误重试状态或附件未就绪 |
| 410 | EVENT_HISTORY_EXPIRED、SOURCE_WITHDRAWN | 重连改读查询快照；撤销原件不下载 |
| 413 | FILE_TOO_LARGE | HTTP 上传体积限制；异步解析的 PAGE_LIMIT_EXCEEDED 写 TaskStatus.error，不截掉后半资料后报告成功 |
| 422 | VALIDATION_ERROR | 请求 Schema 校验失败，含字段名但不含密钥 |
| 429 | BUDGET_LIMIT、QUEUE_FULL | 阻止新付费请求/新任务，返回原因与可恢复方式 |
| 503 | DEPENDENCY_UNAVAILABLE、PRICING_NOT_CONFIGURED | 系统必要依赖/价格未配置；不伪造结果 |

### 8.1 资料列表、版本和任务

DocumentListItem 固定为 `{document:Document, version:Version|null, availability, latest_task:TaskStatus|null}`，详情复用该结构。Document 已含 doc_type，不把 availability 写入持久化 Document。version 严格对应 document.current_version_id，表示当前默认已发布版本；无当前版本则为 null、availability=unavailable。撤销资料的派生 availability 总是 unavailable；其他情况取 version.availability。当前已发布版本不等于任意历史版本，也不等于最新导入尝试。

latest_task 按任务 created_at、task_id 倒序取最新，创建时间为内部必存字段。页面两路索引首先显示 version 的 vector_state/graph_state；没有当前版本时显示 latest_task 的状态，完全没有任务则显示 pending。新版本失败仍显示旧版本的可用性和索引，在单独的任务区域显示失败与重试；不混合成同一个版本的状态。刷新后可凭 latest_task.task_id 恢复抽屉，重试权限以任务 retryable 为准。

availability 过滤只使用上述派生值，不匹配“任一历史版本”；q 匹配标题或当前发布版本 metadata.document_number/case_number。去首尾空白、拉丁字符忽略大小写，字面子串而非正则，空白串返回 422。多项过滤 AND 连接，q 内三个字段 OR。先过滤、再按 created_at/document_id 倒序分页；游标绑定过滤条件与排序键，条件不匹配返回 400。服务端批量关联 Version/Task，禁止用每行单独 HTTP 请求补齐画板 03。

pipeline_revision 必须对解析器/切片/抽取/嵌入模型快照及影响结果的配置形成确定性指纹，不含时间或随机值；相同文件且指纹变化产生新 version_id。/versions 返回该字段及 published_at，用户可追溯重新处理原因。首次发布时间在发布提交时设置，未发布为 null，图重试不得改成新的首次发布时间；内部 stage_artifacts 不暴露私有对象或恢复凭据。

### 8.2 事实与路径诊断

QueryStatus 和 Message 共用 Facts：scenario、location、relevant_date、known_facts[]、missing_fields[]；未知地域/日期为 null，known_facts 仅记用户明确提供或确认的事实。追问先合并旧轮事实，再按本轮明确纠正覆盖，不能把中断答案或模型猜测变成事实。历史 Message 的 facts 为本轮快照，用户和助手投影从同一个 queries.facts 幂等重建。

QueryStatus.reasoning_code 是短决策码：EVIDENCE_SUFFICIENT（可回答）、FACTS_MISSING（需澄清）、NO_RELEVANT_EVIDENCE、EVIDENCE_CONFLICT、APPLICABILITY_UNCERTAIN（后三者依据不足）；尚未完成决策为 null，不返回私有思维链。系统执行失败独立记录 status/warnings，不伪装成正常业务拒答。

path_status 固定含 ordinary、hyde、graph、web、rerank 五键，值为 pending/running/succeeded/empty/skipped/timeout/failed/unavailable。pending 表示未运行，empty 表示执行成功但无候选，skipped 表示策略未调用（含联网关闭、澄清短路），unavailable 表示未配置或依赖不可用；不可混为检索失败。排队初值全 pending；终态不保留 pending/running，未执行路径置 skipped，正在执行且被取消/总超时的路径分别置 skipped/timeout，warnings 记录具体原因。stage 事件可携带完整 path_status，刷新/历史恢复以 QueryStatus 快照为准；path_status 与 facts 随事件快照使用同一 CAS 持久化。

### 8.3 图浏览闭环

画板 05 先用 GET /api/graph/entities?q=名称 获取 entity_id，再调 relations。GraphEntity 含 entity_id、label、entity_type、version_ids，仅暴露可见 knowledge 版本。实体搜索按 label/entity_id 升序稳定分页，q 的空白、大小写及字面匹配规则同资料搜索。

relations 返回 `{paths:Path[], warnings:string[], nodes:GraphEntity[], support_chunks:Chunk[]}`；Path.node_ids 在 nodes 中必须全部可定位，support_chunk_ids 在 support_chunks 中必须全部可定位，页面直接从返回正文/位置打开证据，无需伪造 query_id/E1。业务 max_hops 仅计算实体之间的语义关系，不把回取 RelationEvidence/SUPPORTED_BY 原文算作额外语义跳数。最多 50 路径、150 节点、100 支持切片，按 path_id 稳定顺序保留完整路径，超限加 GRAPH_RESULT_TRUNCATED，不能返回缺证据的半条路径。Path.relation_types 长度必须等于 node_ids 长度减一。

每次请求先冻结已发布且未撤销的知识版本白名单，再查询实体、路径并批量回取原文，响应前复核撤销状态；剔除已不可见路径及孤立节点/切片。实体存在但无匹配路径返回 200 空数组；不存在或范围不可见 404；图服务失败 503。未解析引用仍留 graph_unresolved，不伪造一条可浏览的确定路径。

## 9. SSE 协议

事件 id 为 query_id:seq；seq 从 1 单调递增，以 queries.event_log 中的持久化记录为准。JSON 数据统一带 query_id、seq、event、payload；event 字段与 SSE event 行同值。

采用单文档事件日志：一次 CAS 更新同时提交 answer/evidence 快照、last_event_seq、event_log 新事件和 revision。终态以一次 CAS 同时写 status、finished_at、最终答案、引用结果及唯一终止事件。过滤条件含 query_id、lease_token、revision 和 running 状态，保证并发取消/完成只能有一个终止结果，不依赖 MongoDB 跨文档事务。

运行中进程崩溃后，接管者若发现未到终态且租约过期，以 CAS 写 interrupted、保留已提交 partial 答案并追加 failed 事件，不重新生成；终态记录已有对应终止事件，重连只重放。客户端只读取提交后的日志，不能直接转发尚未持久化的模型 token。

event_log 默认最多 512 条、合计 2 MiB，输入/生成预算保证正常请求远小于该限额；达到阈值前保留终止事件空间并以 STREAM_EVENT_LIMIT 中止，而不是删掉已发送事件或超出 MongoDB 文档上限。7 天后维护任务按 events_expires_at 删除嵌入日志并设 events_expired=true，保留答案与证据及最终 seq；不对 queries 整份文档使用事件 TTL 删除。

```text
id: 80479947-69b1-40c3-93fd-9fc1404dcf88:1
event: started
data: {"query_id":"80479947-69b1-40c3-93fd-9fc1404dcf88","seq":1,"event":"started","payload":{"status":"running"}}

```

| 事件 | payload | 约束 |
| --- | --- | --- |
| started | status=running | 最多一次 |
| stage | name、path_status 可选 | 阶段变化，不代表答案已生成 |
| evidence | items:Evidence[] | 在首个 delta 前发送冻结引用映射；后续不复用 E 编号指向新来源 |
| delta | text:str | 按序追加；每 50～100ms 或每 50 字符聚合一次持久化与发送 |
| warning | code、message | 降级/质量标记，不作为独立答案 token |
| done | status、behavior、citation_validation、last_event_seq | 完整答案和证据持久化后发送，完成重放后关闭连接 |
| failed | code、message、status=failed或interrupted | 区分首 token 前失败与部分生成中断 |
| cancelled | status=cancelled | 后续没有 delta/done |

每个 query 仅一个终止事件：done、failed、cancelled 三选一；interrupted 使用 failed 事件且 status=interrupted。澄清/依据不足仍按 evidence 空列表→delta→done 输出。

重连优先读取 Last-Event-ID；也支持 after_seq，二者同时存在须一致，否则 400。服务器只重放 seq 大于游标的事件；客户端按 query_id,seq 去重。15 秒注释心跳，不占 seq；响应禁缓存、关闭代理缓冲。历史过期返回 410，前端 GET 查询快照并提示无法重播过程，不重新调用模型。

Last-Event-ID 的 query_id 必须与 URL 一致，seq 不得超过当前 last_event_seq；非法或未来游标返回 400。HTTP 错误只在 200 建流之前返回，建流后执行故障使用已持久化 failed/cancelled 终止事件，不向 SSE 中混入 JSON 错误包。

event_log 无条目时不等于 query 丢失：queued 状态保持心跳等待；查询被删或不可见才 404。query 无法正常续跑时使用保存的 partial 文本并要求显式新请求。

## 10. 前端状态与操作映射

导航是单应用内部切换，路由可采用 hash：#/chat、#/documents、#/graph；不引入第二个前端工程。

新建咨询创建新的 session；清空当前会话需明确“删除当前会话”操作，不能把视觉清屏与数据删除混为一谈。上传抽屉关闭后任务继续。图谱空结果显示无匹配路径，区别服务超时。前台不提供训练、数据生成、实验报告和模型发布入口；训练产物及评估文件留在程序外目录，程序仅通过配置读取已部署的回答模型服务。

服务端给的质量标记使用固定中文映射，不能由前端把 limited 翻成“审核通过”。未知效力、自动生成标签、未精排/未联网等都应在对应位置可见。

## 11. 契约检查要求

所有成功/错误样例按核心 Schema 校验；OpenAPI 的外部引用相对于 contracts 目录解析。为 datetime/date/UUID 启用 format 校验，不能只验证字符串类型。Milvus、Neo4j 字段与业务 Schema 的映射写在适配器测试，不直接把 SDK 对象传给 API。

每个 $defs 至少一个直接样例，包含标量枚举；覆盖以实际定义集合为准，不恢复已移除的 Experiment。离线 DatasetSample.evidence 使用 SampleEvidence，不含 query_id，以 sample_id/evidence_id 复合定位；在线 Evidence 必须含真实 query_id。两者共享正文/来源字段规则，只有实际线上查询时才分配查询身份。

OpenAPI 的公共错误响应集中在 components.responses，通过 $ref 复用；各操作只声明可触发的业务错误。live 仅 200，ready 为 200/503，413 仅用于上传体积检查；解析后发现页数超限通过 TaskStatus.error 的 PAGE_LIMIT_EXCEEDED 报告，不能在已返回 202 后补发 HTTP 413。400 负责游标/语义错误，422 负责请求字段，429 负责预算/队列；未预期异常统一 500 ErrorEnvelope（全局处理，不在每操作复制），日志保留 request_id，不泄露堆栈或密钥。

实现增加字段时先更新 Schema 和文档，再更新服务/前端，禁止两个模型各自另定义一套 Evidence 或 QueryStatus。
