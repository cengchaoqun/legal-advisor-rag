## 3.1 本轮在真实数据上发现并修复的缺陷

1. **证据策略误判版本冲突**（`retrieval/policy.py`）：原实现把所有证据的 `version_id` 去重后判断是否 >1，
   导致任何"多份资料"的组合在生效期未知时都被判 `EVIDENCE_CONFLICT`、返回"依据不足"。
   真实语料全部 `effectivity_unknown`，因此 55 份资料导入后**每一个问题都答不出来**。
   已改为按 `document_id` 归组（Evidence 是契约对象不能加字段，由调用方以 `evidence_id -> document_id` 传入），
   只有同一份资料出现多个版本且都缺生效信息才算冲突；新增 2 项回归测试。
2. **失败查询丢失证据快照**（`retrieval/query_pipeline.py`）：证据只以 SSE 事件发出、未落库，
   生成阶段失败时查询对象里 `evidence` 为空，与"答案/证据/事件一致提交"不符。
   已在生成前用 CAS 写入证据快照 + facts + path_status，失败时也保留（实测 6 条证据完整可读）。
3. **worker 冷启动导致首个查询检索超时**：BGE-M3 首次加载约 50 秒，超过 `timeouts.ordinary_seconds=10`，
   路径状态被记为 `timeout`。已在 worker 启动时预热嵌入模型。
4. **采集脚本吞掉 robots 禁令**（`scripts/collect_sources.py`）：`can_fetch` 为 False 时抛出的异常被同一
   `try/except` 捕获后继续抓取。已拆分为"明确禁止则跳过 / 读取失败按未声明处理"。

## 6. 环境偏差（已记录于依赖锁定）

- MinIO 开源版归档、二进制 410、镜像 403 → 对象存储改用 S3 兼容的 SeaweedFS。
- 项目路径含中文导致 `.pth` 乱码 → 以非可编辑方式安装包，改代码后需 `--reinstall-package legal-rag`。
- Mongo 镜像源长时间阻塞期间曾用官方 Windows `mongod` 完成测试，镜像可用后已切回 `mongo:7.0.14` 容器。
- **GPU 认知更正**：此前记录“本机无 GPU”有误。实测存在 `NVIDIA GeForce RTX 5060 Laptop GPU`（驱动 610.47，计算能力 sm_120，显存 8.0 GiB）。原 torch 为 CPU 轮子，已在 `pyproject.toml` 中把 `torch` 固定到 PyTorch 官方 `cu128` 索引，现为 `torch 2.11.0+cu128` / CUDA 12.8，`torch.cuda.is_available()=True`，GPU 矩阵运算实测通过。
- **显存低于设计建议值**：`training.minimum_candidate_vram_gib = 16`，本机 8.0 GiB。LoRA 在 1.5B 基座上实测可行（bf16 + 梯度检查点 + 序列 2048 + 批 1），但属于低于建议值的运行，结果需按实际记录。
