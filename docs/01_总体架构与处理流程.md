# 总体架构与处理流程

版本 V0.4，2026-10-21。本文参数是首版设计默认值，不是已测性能或法律正确性承诺；变更需记录原因及评估配置。

## 1. 运行拓扑与技术决策

```text
浏览器 http://127.0.0.1:8000
  └─ FastAPI：静态前端、REST、SSE、对象资源代理
       └─ MongoDB：提交任务、读取事件、查询来源

worker：领取导入/查询任务，运行 LangGraph，维护租约与预算
  ├─ 本地 BGE-M3 单实例：导入和查询共享；CPU 阻塞工作移出事件循环
  ├─ 微调后的回答模型服务：独立地址、鉴权和模型版本；辅助模型/重排另行配置
  ├─ Milvus：稠密/稀疏向量
  ├─ Neo4j：关系、实体、证据定位
  ├─ MongoDB：权威切片、状态、证据快照和事件
  └─ MinIO：原件与解析结果；训练产物不由业务程序管理

程序外：独立训练→评估→合并模型→部署推理 API→配置到 worker；前台无训练入口
```

默认 API 8000、MongoDB 27017、Milvus 19530、Neo4j Bolt 7687/控制台 7474、业务 MinIO 9000/9001。只绑定本机或受控网段；Milvus 内部对象存储不占用业务 MinIO 的宿主端口。实际 Compose 固定镜像标签并记录到 dependency-lock.md，禁止依赖未记录的 latest。

API 不执行长任务，也不加载嵌入模型；worker 在一个进程中共享模型，查询槽位 1、导入槽位 1。Embedding 推理互斥，导入每批 4 个切片后让出执行机会。需要远程嵌入时必须保持 BGE-M3 模型与稀疏输出契约一致，不能静默替换为另一种稠密模型。

首期不使用 LangGraph 持久化检查点：图状态用于一次执行，恢复由 MongoDB 的阶段产物和确定性重试完成。将阶段状态持久化不等于可从任意推理 token 续跑。

## 2. 边界和适配接口

| 模块 | 输入/输出 | 约束 |
| --- | --- | --- |
| parser | 原件引用→正文、页/条款定位、资源 | 文本 PDF/MD 默认；扫描件无法解析则 unsupported，不生成空成功 |
| extractor | 切片及标题→元数据、实体、显式引用、质量标记 | 所有推断保留方法版本，缺失值为 null |
| embedding | text[]→dense[1024]、sparse(token_id,weight)[] | 同模型快照导入/查询；稠密归一化、稀疏 token 编号不转成字符串语义词 |
| vector_store | 向量＋版本白名单→Candidate[] | 稠密/稀疏是本地普通路径内部的混合检索 |
| graph_store | 结构化实体及过滤→Candidate[]、paths[] | 模板查询、最大 2 跳、不运行任意生成 Cypher |
| web_search | query、allowlist→WebCandidate[] | 手动开启；无服务配置返回 unavailable，不生成假网页 |
| reranker | query、Candidate[]→排序及分数 | 超时保留本地融合顺序，标注降级 |
| generator | 问题、事实、证据→文本流 | 不能调用数据库或把证据中的指令作为系统提示 |
| 离线 evaluator（不属于应用模块） | 输入、输出、证据→自动评估文件 | 在独立训练流程执行，不设置业务 API 或前台页面 |

## 3. 输入与业务默认值

场景枚举 wage_arrears、termination、economic_compensation、other。other 不自动扩展语料范围：可检索一般说明，但明确首版范围；没有证据则给出依据不足。

jurisdiction 固定 CN-national，用户事实中的地域另存 facts.location。relevant_date 可为空；涉及时间冲突且影响判断时先澄清，不能一律选择最新版本。无需对每个问题都询问全部事实：只有缺失事实影响当前问题的证据选择或结论时触发澄清。

问题最大 2000 字符，最多附加 2 个会话文件；单文件 20 MiB、PDF 最大 200 页；展示数据目标上限 100 份文档、5000 个切片。超过上限返回限制错误，不能隐式收费扩容。

## 4. 导入图与任务恢复

顺序：validate→save_original→parse→split→extract→write_vectors→write_graph→publish。

1. validate：检查 MIME、后缀、大小和路径安全；对象键由系统生成，不将用户文件名当服务器路径。
2. save_original：保存摘要和对象引用；默认上传按 scope/session/内容摘要去重，显式 replace_document_id 则只在目标资料内去重。可复用原始对象，但不能把其他资料的身份作为替换结果，规则详见数据契约。
3. parse：MD 保留标题、条号、代码块；PDF 默认轻量文本提取并记录页码。MinerU 是可选增强解析器，未配置扫描/OCR 服务时返回 PARSER_UNSUPPORTED。
4. split：优先按法规条款/案例基本事实、裁判理由分段；目标 400～800 中文字符，软上限 1000、重叠 80；超长单条按句分片并保留条号和 part 序号。语义完整优先，表格不能无标记拆成互不关联的行。
5. extract：全局元数据来自标题/原文，不确定日期保留 null；只在原文包含命中别名或条号时生成对应实体证据。模型结构化输出校验失败最多修复一次，再退回规则抽取并标记警告。
6. write_vectors：向量校验维度和数值，按确定性 chunk_id upsert。向量可用为问答最低工程条件。
7. write_graph：写实体和有原文支持的关系，无法定位引用版本记 unresolved_citation。该阶段失败可发布受限版本；完成为空图是合理结果，需显示“无可确认关系”，不能把空图当技术失败。
8. publish：先持久化完整正文与阶段输出，再用 MongoDB 单文档 CAS 切换 publication_state。查询只使用数据库中的可见版本白名单，不通过 Milvus/Neo4j 单侧写入判断发布完成。

阶段产物存 MongoDB/MinIO；任务 stage_success 清单含输入摘要、产物位置和 extractor/embedding 版本。重试从失败阶段开始，若前置版本改变则重跑相关后续阶段。失败尝试上限 3 次；预算不足、非法输入、未支持格式不自动重试。

worker 租约 60 秒、每 20 秒心跳，领取任务采用 MongoDB 原子 find_one_and_update。CAS 更新必须包含 lease_token，旧 worker 不得覆盖新持有者。失联导入租约到期可重新排队；已开始流式输出的查询标记 interrupted，不自动生成第二份混杂答案。

## 5. 可用性和法律质量分离

| 状态 | 工程条件 | 咨询使用方式 |
| --- | --- | --- |
| available | 正文/向量完成、图构建成功、关键元数据齐全 | 仍须按原文和适用条件回答；不是法律审核通过 |
| limited | 正文/向量完成，部分元数据缺失或图失败/引用未解析 | 正文可召回；引用显示限制；不作未知效力或版本的确定性判断 |
| unavailable | 无有效正文、向量未完成、撤销或未发布 | 不进入咨询候选 |

quality_flags 记录 metadata_missing、effectivity_unknown、citation_unresolved、graph_unavailable、source_access_limited、parser_partial 等。effectivity=known_current 只能来自具有原文定位的来源记录，不能仅靠模型置信度设定。

自动质量校验检查“来源是否存在、字段是否自洽、引用是否可定位”，不等于专业审查法律适用性。用户不需要点击人工确认或审批发布。

## 6. 更新、历史与删除

document_id 代表稳定资料身份，version_id 代表内容＋提取配置的一次不可变版本。新文件与已有资料的身份关联不靠文件名猜测；显式 replace_document_id 或可靠文号/案号映射，否则作为新资料创建并标记可能重复。

current_version_id 表示当前默认资料版，不代表该法律当前有效。明确相关日期时可使用仍保留的历史版本，并按生效/失效区间筛选；日期未知不得抹去有冲突的旧版本。

撤销先设置 tombstoned，使新查询快照立即排除该资料，再异步清理两路索引。既有回答保存证据快照用于审计，来源详情显示“资料已撤销”；不继续公开对象文件下载。已运行查询输出前重新校验被撤销标识，排除被撤销证据或中止当前轮。

## 7. 查询图

validate→history_and_facts→route→snapshot→retrieve→fuse→rerank→evidence_policy→generate→finalize。

history 最多最近 6 条已完成消息，保留未完成轮次的用户事实但不将中断答案作为已确认依据；总历史字符上限 4000。查询创建时唯一写入 user 消息，finalize 唯一写 assistant 消息，重放 SSE 不重复写历史。

route：最多一次结构化模型提取；直接可识别的法规名/条号走规则。若需要澄清，返回 clarification 结果，保存问题并结束，不执行四路检索。追问作为新 query，基于前轮事实补全。

snapshot：冻结 workspace、document/version 白名单、范围与相关时间；所有路径、证据详情必须使用同一快照。元数据缺失资料不被硬过滤掉，但进入 limited，并由证据策略决定可支持的回答强度。

retrieve 节点内部 asyncio.gather 运行 ordinary、hyde、graph 和可选 web，各自返回独立键，异常转换为该路径状态；不让多个 LangGraph 并行节点覆盖同一列表。节点仅返回状态增量，避免原地修改全局 state。

## 8. 检索参数与融合

| 参数 | 初值 |
| --- | --- |
| 普通路径内部稠密/稀疏 Top-K | 各 20；按加权排名融合后取 20 |
| 普通路径内部权重 | dense 0.7、sparse 0.3；使用 k=60、rank 从 1 开始的加权 RRF；不用未校准原始分数相加 |
| HyDE | 最多 1 份、300 字；检索取 20，不作为证据 |
| 图谱 | 最大 2 跳、50 条路径，映射去重证据后取 20 |
| 本地加权 RRF | k=60；ordinary=1.0、hyde=0.7、graph=0.8 |
| RRF rank | 从 1 开始，score(d)=Σ weight/(60+rank(d)) |
| 联网 | 手动开启时最多 5 条，允许域名验证，最多抓取 3 篇正文 |
| 精排输入/输出 | 最多 30 条；最终不超过 6 条 |
| 上下文 | 候选证据正文累计上限 2400 字符；最终完整输入须按回答模型 tokenizer 限制到 1024 tokens，必要条件不能静默截断 |
| 默认生成 | temperature=0.1，max_new_tokens=512；默认回答模型输入最多 1024 tokens，服务上下文 1536 tokens |

同 chunk_id 在同一路只计一次，不同路径命中可累加贡献并保留 recall_sources。图谱证据排序按匹配实体数降序、路径长度升序、稳定 chunk_id 升序，避免天然无序结果进入 RRF。

本地 RRF 后添加联网候选并按规范化 URL＋正文摘要去重；只对可获取、许可展示的正文建立“网页原文”引用。只有搜索摘要时标为 web_snippet，只能支持“搜索线索”，不能伪称已读原文。每份外网证据使用独立 source_id，不能套用本地 chunk_id。

断崖策略：精排后最多考察前 6 条，从第 2 条之后的相邻位置找绝对差≥0.25且相对差≥0.35的首个位置，至少保留 2 条（候选本就少于 2 时保留已有条数）。绝对差为 s[i]−s[i+1]，相对差为绝对差/max(abs(s[i]),0.00000001)；命中后保留至 i。分数相同按 source_id 升序。参数仅为起步启发式；不同重排模型须重校准，无相关性时不能为了保留 2 条而强行回答。

## 9. 证据策略与输出

behavior=answer：有直接相关且可定位的证据；限制性结论清楚标示条件。behavior=clarify：必要事实缺失而用户可补。behavior=insufficient：无证据/无法消解冲突/只剩不适用资料。自动模型判定保留 reasoning_code 和证据 ID，不保存或展示私有思维链。

事实快照、稳定决策码以及 ordinary/hyde/graph/web/rerank 五键 path_status 统一遵循[数据契约 §8.2](02_数据与接口契约.md#82-事实与路径诊断)。澄清短路的未调用路径为 skipped，成功空结果为 empty，禁用联网不记作故障；这些状态随查询持久化并可刷新恢复，不只保存在前端内存。

咨询 generate 节点固定使用配置的微调模型服务，提取/HyDE 可使用独立辅助云模型。模型服务不可用时明确错误，禁止静默退回未微调云模型；查询记录保存模型名与部署产物摘要。最终提示词固定四部分：范围、用户事实、编号证据、输出规则。输出“摘要、依据与条件、需补充事项”，引文 [E1] 必须对应当前 evidence_map。原文和网页是不可信数据，不具备修改系统规则的权力。

SSE 先给阶段，再发送冻结证据映射，随后传文本增量；最后校验引用存在性。无法验证的引用保留原始输出用于评估，返回 citation_validation=failed 与警告，界面不生成不存在的可点击链接，不把回答标记为“引用全部有效”。

## 10. 超时、重试与失败

查询总时限 120 秒，排队时限 60 秒；普通/图路径 10 秒、HyDE 15 秒、联网 15 秒、重排 10 秒、生成 45 秒；真实并行与总截止时间同时生效。导入每阶段 10 分钟截止，首期不提供硬实时 SLA。

网络限流/短暂 5xx 可退避重试 1 次（2 秒）；付费重试也需预算预留。生成收到首个 delta 后不自动重试；流断标记 interrupted。rerank 失败使用 RRF＋网络列表稳定顺序并标记降级，不能声称完成精排；普通与 HyDE 全失败且图无证据时 insufficient，查询核心依赖不可用且无法完成流程则 failed。

客户端断连不取消任务：SSE 从持久化序号重连。用户显式取消才设置 cancel_requested，worker 在阶段边界检查，已发起付费请求可能仍计费；终态输出取消事件，不保存为完整答案。

SSE 事件与累计答案、终态存于同一个 queries 文档，以租约＋revision CAS 原子更新；禁止分开写完成状态与 done。worker 崩溃后，租约到期的 running 查询原子补记 interrupted/failed 终止事件，不重新调用模型。具体嵌入日志与重连规则见数据契约。

## 11. 工程依据与验证边界

LangGraph 的异步图调用和默认字段覆盖行为依据[官方图 API](https://docs.langchain.com/oss/python/langgraph/use-graph-api)，本版以单个 retrieve 节点汇合路径结果避免并发字段冲突。

BGE-M3 的混合输出与 1024 维依据[官方模型卡](https://huggingface.co/BAAI/bge-m3)。在线重排接口依据[百炼文本排序](https://help.aliyun.com/zh/model-studio/text-rerank-api)。供应商、地域和账号可用性仍需探针验证，不能因为文档可查就宣称已连通。
