# 设计复核与 Agent 开工提示词

复核日期：2026-10-21。基线：V0.4 契约修订；不改变单人、本机学习展示的产品范围。

## 1. 结论与适用范围

设计具备进入 P0 环境验证和后续分阶段实现的条件，不能据此称为可直接生产上线。当前目录仍是设计与静态画板，没有应用、真实数据、数据库运行记录、训练产物或性能/恢复验证。总纲明确排除了账号权限和生产高可用，300 元是开发及短时演示预算。

这里的“可开工”指业务边界、对象、接口、流程、阶段依赖和验收标准已能指导实现；不表示外部依赖兼容性、资料可访问性、硬件和模型效果已验证。若目标变成公网正式服务，需要另行确定用户身份/权限、数据保留和删除、备份恢复、容量与可用性目标、监控运维和长期运行预算，再进行相应实现与验收；本次不擅自扩展该范围。

## 2. 本轮修订

| 原问题 | 修订结果 |
| --- | --- |
| 资料列表与过滤不闭环 | Document 原有 doc_type 保留；列表/详情共用 DocumentListItem，直接带当前 Version、派生 availability、latest_task；可用性按当前发布版本过滤，无当前版本为 unavailable，新导入失败不覆盖旧版本 |
| 离线样本复用在线 Evidence | 新增 SampleEvidence，去掉 query_id；E 编号以 sample_id 定位；在线 Evidence 仍要求真实 query_id |
| 版本处理来源缺失 | Version 必须返回 pipeline_revision、published_at，内部 stage_artifacts 不对外泄露 |
| 事实和降级诊断缺失 | Message 与 QueryStatus 共用 Facts；QueryStatus 增加 reasoning_code、五路 path_status，定义初始/短路/降级/终态语义 |
| 错误和样例不精确 | components.responses 复用公共错误，各操作声明实际错误；全部实际 $defs 有直接样例，增加跨对象检查和错误反例 |
| 图谱页面缺少实现入口 | 增加中文实体搜索，关系响应带 nodes、support_chunks，使标签与原文无需借用 query 身份即可展示 |
| 资料搜索/任务恢复缺口 | 定义 q 搜索标题/当前版本文号/案号；latest_task 使刷新后仍能找到重试任务 |
| P3 先于 P5 要求真实回答 | P3 先验链路与明确标识的离线替身，P5 模型部署接入后补验真实三场景，P6 前必须完成 |

实际复核前有 17 个定义、22 个操作、7 个直接样例；本轮变为 23 个定义、23 个操作、23 个直接样例。原问题清单的 18/25 与当前文件不一致；Experiment 已不属于本版业务模型，不为覆盖旧清单而恢复。

## 3. 验证与后续门槛

在项目根目录执行：

```powershell
python -X utf8 docs/check_design.py
```

检查所有本地引用、契约引用、默认参数、23 个定义的直接样例、接口状态码与关键视图闭环，并验证离线证据带 query_id、在线证据缺 query_id、版本缺处理指纹、路径状态非法四个反例会被拒绝。该脚本不是完整的标准 Schema/OpenAPI 验证器，更不替代 P0～P6 的应用测试。正式开发仍须以标准工具验证领域模型、HTTP 响应和 SSE 行为。

本轮另使用临时目录安装的 jsonschema、openapi-spec-validator 执行 `docs/check_design_standard.py`：Draft 2020-12 Schema 自检、开启 FormatChecker 的 23 个样例、OpenAPI 3.1 的 23 个操作均通过。工具先检查外部引用，再等价绑定为内部组件，避免访问声明性的 local.invalid 地址；没有联网调用业务 API。复跑该脚本需在所用 Python 环境提供这两个校验依赖，不要求安装到系统全局。标准校验通过代表契约结构有效，不代表实际服务行为已经实现。

实现必须通过 [交接验收](04_开发交接与验收.md) 的 T01～T33；真实资料、四库连接、付费账户、训练及在线模型接入分别取得真实执行证据。无法运行的检查写“未执行/阻塞”，不能写“通过”。

## 4. 可直接复制给开发 Agent

```text
请在当前项目根目录实施“掌柜智库·劳动用工咨询”，直接开始开发，不要只回复计划。

先检查适用的 AGENTS.md 和现有文件，保护用户已有修改。按以下顺序完整阅读当前设计：
1. README.md、掌柜智库_概要设计总纲.md；
2. docs/01_总体架构与处理流程.md、docs/02_数据与接口契约.md；
3. docs/03_资料微调与自动评估.md、docs/04_开发交接与验收.md、docs/05_微调模型部署与程序接入.md；
4. docs/contracts/核心对象.schema.json、openapi.json、默认配置.json、契约样例.json；
5. designs/界面设计说明.md、designs/法律咨询工作台_低保真.pen；
6. docs/06_设计复核与开工提示词.md。
以当前 V0.4 修订为基线，不读取历史归档来覆盖当前决策。遇到冲突按总纲优先级处理，同步修正文档与机器契约，不自行发明另一套数据模型。

先运行 python -X utf8 docs/check_design.py，核对当前实现状态，然后按 docs/04 的 P0→P6 推进。先建可安装的 Python 3.11 src 工程、锁定依赖、配置校验、领域模型、离线预检和健康接口，再逐步实现真实存储、导入、检索、咨询及统一前端。每阶段落实关键行为测试和验收证据，通过后继续下一阶段；不要每阶段都停下来等批准。将阶段进展、实际运行命令和阻塞项保存在 docs/开发进度.md，便于中断后接续；未执行的测试明确标注。

必须遵守以下约束：
- 仅实现单人、本机受控展示；不新增登录、多租户、人工审核、训练/实验前台或模型切换入口。代码注释、交接和进度文档使用中文，注释解释目的与容易误解的逻辑。
- 资料列表/详情遵循 DocumentListItem；availability 按当前发布版本过滤，最新任务独立展示；首次无发布版本为 unavailable，替换失败保留旧版本。不要靠逐条 HTTP 详情请求补齐列表。
- 离线样本用 SampleEvidence，不填假 query_id；在线 Evidence 只能绑定实际 query。统一 Facts、Message、QueryStatus 和 PathStatus；版本返回处理指纹与首次发布时间。
- 图谱页面实现中文实体搜索、节点标签和支持原文；所有检索、图路径、原件读取执行同一知识/会话/版本可见性规则，未知关系不造边。
- 导入阶段可恢复，写入幂等；查询答案/证据/事件/终态以单文档 CAS 一致提交；SSE 重连仅重放，不重新调用模型。落实撤销、租约失效、取消、预算并发与部分生成失败测试。
- 最终咨询回答必须接入程序外真实微调并部署的模型；抽取/HyDE 使用独立辅助客户端。模型不可用时明确失败，禁止静默用辅助云模型冒充。P3 允许明确标识的离线替身验证链路，但真实三场景问答必须在 P5 接入后、P6 前补验。
- 总预算上限300元，默认API80/GPU150/预留70，paid_execution_enabled默认false。开发和离线测试继续执行；付费API、充值、租赁、预算开关变更只在已有明确授权和有效价格预检范围内执行，禁止自行租GPU或绕过预算。遇到外部账户、密钥、资料或硬件阻塞，记录具体原因，并继续不受阻塞的工作。
- 禁止用 mock 数据、示例ID、空数据、假日志或虚构指标冒充真实资料、连通、训练和模型接入。固定测试集不进入训练或知识库；自动银标结果如实报告，不能宣称专业法律准确率。
- 完成标准 Schema/OpenAPI 校验以及 docs/04 的 T01～T33；真实中间件集成和在线模型接入与离线测试分开报告，不把契约检查通过当成应用已完成。

常规可逆技术选择自行决定并记录；不要重新访谈已确认业务。只有确实需要用户提供外部信息或授权时才提出具体问题。每阶段汇报实现范围、修改文件、测试命令及结果、剩余工作；最终提供可复制的启动、导入、测试、微调、部署和验收命令。目标是可运行、可追溯的真实本机演示系统；未经实现及验证不得声称生产就绪。
```
