# 资料、微调与自动评估

版本 V0.4。用户已确认全部自动生成和自动评估；不设置人工审核或标注任务。本文中的样本数量、训练参数和预算分配为首期默认配置，实际不足须在报告中记录，不能虚构资料、标签或训练结果。

2026-10-21 更新：用户指定外部单卡24GB、Qwen3-8B、SFT+LoRA；实际数据、长度探针与命令以[Qwen3操作手册](08_Qwen3-8B微调与接入操作.md)为准。当前工程银标为180/40/57，并未完成专业语义评审或真实训练。

## 1. 起步语料与获取规则

初始目标为 6 份全国层面的法规/解释/官方业务资料，以及 18 份公开案例或官方案例摘要（每场景至少 6 份）。覆盖工资拖欠、劳动合同解除、经济补偿；同一文档可跨场景标记，不重复计数。

候选主题：劳动法、劳动合同法及配套规定、劳动争议处理程序、工资支付、最高人民法院劳动争议相关司法解释。该清单是检索主题，不宣称某个未取得的版本当前有效；先获取官方文本、版本和来源，再建立语料清单。

优先来源：[国家法律法规数据库](https://flk.npc.gov.cn/)、[最高人民法院](https://www.court.gov.cn/)、[人民法院案例库](https://rmfyalk.court.gov.cn/)、[人力资源和社会保障部](https://www.mohrss.gov.cn/)。本轮只核对资料入口，未下载真实法规或案例；法规数据库直接访问出现 403，不能把入口可识别写成已获得资料。

数据执行流程：公开站点检索→读取可访问全文/官方案例发布页→记录来源与保存时间→生成规范 Markdown/保留原 PDF→内容摘要与去重→自动解析入库。优先官方发布页；需要登录、验证码、授权或不允许自动获取的来源，记录 access_blocked，并改用可公开访问的官方等价页面。不得绕过限制或用搜索摘要补造成完整判决书。

官方案例摘要是 case_summary，完整裁判文书是 judgment，两者用 source_subtype 区分。无法获得案号时保存官方案例编号和 URL，case_number=null；不能生成假案号。网页只有摘要时与完整案例分开统计。

## 2. 来源清单与批量采集限额

每个条目至少保存：source_id、title、URL、publisher、source_type/subtype、scenario_tags、retrieved_at、content_sha256、local_object、version_notes、access_status、usage_notes。无正文的条目只保留在待获取清单，不计入可检索资料。

source_manifest.jsonl 每行一条，另生成来源统计 source_summary.json。URL 规范化时去除追踪参数，不删除决定资料版本的查询参数。相同正文/同案多渠道发布视为同源组，不作为多份独立资料或不同测试组。

单域名默认并发 1、请求间隔至少 2 秒、每次任务上限 30 页；失败退避，不反复刷新验证码。首期不自动抓取全站，也不购买第三方数据库。不能公开再分发的全文只保留来源索引与必要可展示片段，演示仓库不打包无权限原件。

## 3. 自动抽取与质量等级

元数据采用标题/文号/日期规则＋结构化模型提取，重要字段附原文位置。规则只验证结构和一致性：例如日期先后、条号出现、引用短引确实属于正文。模型 confidence 不能单独使未知效力变成已知。

关系自动校验：引用标题＋条号＋版本线索能够唯一解析，且引用文字有来源→source_supported。缺少版本、同名或证据不存在→unresolved，不生成确定 CITES。Issue 的规范词表首期限定三场景及其少量别名，避免自由生成上千主题。

quality_flags 不触发人工门禁：向量正文就绪即可 limited，关键条件完整可 available。source_supported 只表示原文支持关系，不等于关系具有确定法律效力。对未知日期或效力的资料，允许解释原文及限制，不允许给出确定适用结论。

## 4. 样本来源划分先于问题生成

训练/验证/测试目标 300/60/90 条，分别覆盖三个场景，测试每场景 30 条；五类能力在三个 split 都出现，测试每能力至少 10 条。题目数量不足时报告实际值和原因，不重复改写凑满。

首先按 origin_group_id 划分源组，再生成问答：

- 同一案件、同案摘要、转载、近重复版本和同一事实情形属于同组，不得跨 split。
- 从法规直接生成的问题，以条款版本及相邻适用条件组为原始组，不能将同条款的问答改写拆入多个 split。
- 案例型问题以案例族为原始组；共同引用的一般法规可作为背景检索材料，不将所有案例仅因引用同一法律合并为一个组。报告明确这是“已知知识条件下的新问题表现”，不宣称未见法规泛化。
- 如同时做法规留出测试，单独记录 held_out_provision_groups，并禁止训练标签使用这些组；与主测试分开报告。
- 用固定随机种子 42 和划分清单记录组归属；先保存 split_manifest，再调用模型生成。不能先生成全部样本再随机逐行打散。

固定测试题和标准答案不入训练集，也不作为线上知识切片导入。评估检索允许获取公开原始证据，不能获取测试答案；这是 RAG 获取知识与标签泄漏的边界。

## 5. 自动数据生成与过滤

生成器从单个源组取一到三个有来源片段，生成问题、预期行为、逐条引用答案与能力标签。所有标签固定 label_type=synthetic_silver，不命名 gold/专家标注。

五类能力为 terminology_format、faithfulness、integration、citation、abstention，直接对应原始《微调内容》的术语格式、忠实回答、整合、引用、拒答。abstention 细分事实缺失→clarify，证据无关/冲突→insufficient；不能把所有困难题都标为拒答。

处理顺序：

1. JSON Schema 校验；资料 ID、原文范围和所有引用必须存在。
2. 检查空内容、长度、条号/数字是否无依据增加，目标答案中的 [E#] 是否在证据中。
3. 问题和来源摘要去重；去掉与其他 split 近重复问题。近重复阈值初值：字符 3-gram Jaccard≥0.8 判同族，并保存去重方法。
4. 第二次模型调用检查“答案是否由给定证据支持、是否漏掉明显条件、预期行为是否合理”，输出结构化通过/失败及短理由，不输出私有思维链。
5. 不通过最多重生成一次；仍不通过丢弃，保存失败统计。基础校验或语义检查失败样本不流入训练。
6. 固定最终数据摘要，保存每条样本的源组、提示词版本、生成模型、自动检查结果及消耗。

缺少独立评审模型预算时允许生成与评审使用同一模型的独立调用，但必须标明同源偏差；换提示词不等于独立专家。自动检查通过不能写成“经法律审核”。

## 6. 数据文件与训练输入

规范样本遵循 [DatasetSample](contracts/核心对象.schema.json)。训练导出额外生成 messages 格式的 train.jsonl/validation.jsonl，测试保留 test.jsonl 不混入训练命令。

离线 evidence 必须为 SampleEvidence[]：字段与在线 Evidence 一致但没有 query_id，evidence_id 只在 sample_id 内编号。禁止为了通过校验填充虚构查询 UUID；评估预测按 sample_id 关联，只有真实在线查询才生成 query_id。条件覆盖标签等保存在 EvaluationLabel sidecar，不混入训练输入。

示意（内容占位，不计入真实样本）：

```json
{"messages":[{"role":"system","content":"仅根据编号证据作答，区分条件和未知信息；不得补造依据。"},{"role":"user","content":"问题：示例问题\n证据：[E1] 来源片段\n请输出摘要、依据与条件、需补充事项。"},{"role":"assistant","content":"条件分析示例。[E1]"}],"sample_id":"demo_only","label_type":"synthetic_silver"}
```

最终训练使用基础模型自身 chat_template。只对 assistant 标签计算损失，user/system/padding 的 label=-100。不得一边训练 system/user 的逐字复述，一边把结果解释成问答能力提高。

max_seq_length=1536 包括提示词与目标答案；超过长度先减少检索背景到保留必要条件的证据集合，仍超长则剔除并计数。不能静默截断目标答案或切掉关键例外。目标输出最多 512 tokens；数据导出与评估共享一个 prompt_builder。

## 7. 一次真实微调的默认配置

基础模型选 Qwen/Qwen3-8B，固定模型 commit/revision 后实验。模型卡提供该开源指令模型的加载与 chat_template 用法，见[官方模型卡](https://huggingface.co/Qwen/Qwen3-8B)。这是低预算实验基线，不是“当前最佳法律模型”的断言。

训练环境：Linux GPU，优先租用可用显存≥24GB 的单卡；实际运行须先做显存与速率探针，该容量不构成完整训练必然成功的保证。用 Transformers Trainer＋PEFT，不为首期引入分布式训练、RLHF、DPO 或训练平台。

| 参数 | 初值/规则 |
| --- | --- |
| 方法 | SFT＋LoRA，基础模型权重冻结 |
| target_modules | q_proj、v_proj；预检模块实际存在，否则停止并修正配置 |
| r / alpha / dropout | 8 / 16 / 0.05 |
| sequence_length | 1536 |
| micro_batch / gradient_accumulation | 1 / 8，有效 batch=8 |
| epochs / learning_rate | 2 / 0.0001；首次完整训练不做多轮网格搜索 |
| warmup_ratio / weight_decay | 0.03 / 0.01 |
| optimizer | AdamW，trainable 参数仅 LoRA |
| 精度 | 本24GB配置固定 bf16；不支持时停止，不静默切CPU/FP16/QLoRA |
| 稳定性 | gradient_checkpointing=true、max_grad_norm=1.0、seed=42 |
| 保存/验证 | 每 epoch 保存和验证；保存 best validation loss 对应适配器，不用测试集挑 checkpoint |
| 推理比较 | temperature=0、do_sample=false、max_new_tokens=512，基础与适配模型相同 |

先用 20 条样本跑 10 个优化步骤做 smoke，计时与显存日志通过后才运行正式样本。300 条、每 epoch 分批累积时，约 38 个优化步骤/epoch；实际 global_step 以框架日志为准，不承诺固定时长。OOM 先缩短到 1024 并重新校验样本，不悄悄更换基础模型或删除测试难题。

LoRA 机制和配置参考 [PEFT 官方文档](https://huggingface.co/docs/peft/main/en/task_guides/lora_based_methods)。依赖在 GPU 环境探针后锁定，并保存 CUDA/torch/transformers/peft 版本；本轮未安装或运行这些依赖。

## 8. 前后比较的两条轨道

微调与评估在程序外执行，评估后将该微调模型部署并接入咨询 generate 节点。辅助抽取/HyDE 的 qwen-flash 不是最终咨询回答模型。禁止将辅助云模型与 LoRA 模型的差异当作微调因果对比。

轨道一：固定证据、固定提示词、相同 8B 基础权重→base_predictions；加载其 LoRA→adapter_predictions；同一测试集、长度与解码。该轨道评价生成端差异。

轨道二：固定在线生成模型与测试问题，对比 ordinary、ordinary+hyde、ordinary+graph、ordinary+hyde+graph+rerank；联网默认不参与主实验，另开 web_enabled 条件记录来源快照。该轨道评价检索组件差异。

同一个模型的测试答案必须在测试集冻结后生成；验证集用于调参、测试集只作最终报告。复跑记录新的 experiment_id，保留上一结果，不覆盖不理想实验。

## 9. 自动评估指标与口径

| 指标 | 计算和分母 | 限制 |
| --- | --- | --- |
| 来源可定位率 | 有原文定位的最终证据数 / 最终证据总数 | 只代表可追溯，不代表支持全部结论 |
| 引用 ID 有效率 | 实际引用且存在于 evidence_map 的引用次数 / 所有引用次数 | 无引用答案单列 no_citation，不按 100% 算 |
| 回答行为准确率（银标） | 与自动标签 answer/clarify/insufficient 一致的题数 / 测试题数 | 自动标签可能错误 |
| 格式遵循率 | 三段式或指定拒答格式满足题数 / 适用题数 | 不衡量法律内容对错 |
| 银标证据 Recall@K | Top-K 覆盖的银标相关 chunk 数 / 银标相关 chunk 总数 | 银标非穷尽相关集，漏标会影响结果 |
| 自动忠实性评分 | judge 对每题给 1～5 分及 unsupported_claims，报告均值/分布 | 同源模型偏差，不称法律准确率 |
| 条件覆盖率（银标） | 覆盖的 required_points / 银标 required_points | required_points 为自动生成并冻结的评估 sidecar 标签 |
| 运行指标 | 每题总耗时、阶段耗时、调用 token、费用、错误/降级次数 | 不保证生产 SLA |

正确拒答和过度拒答分别统计；answer 样本被拒答计入过度拒答。引用错条、版本未知却作确定性断言、编造数字分别计数；未发生样本不等于模型无此风险。

样本数、失败数和每场景分母同时展示，失败题不能从分母删除后美化平均分。数据质检剔除发生在冻结测试集之前，模型执行失败发生在冻结之后，应计入运行失败率。

工程通过门槛：真实训练日志与适配器存在且可加载；两种预测齐备；实验配置一致；报告完整；费用不越界。自动效果指标允许无提升或退步，照实解释，不把“项目跑通”混同“法律能力已证明”。

## 10. 产物与展示

每次 run 至少导出 config.json、environment.json、data_manifest.json、train_log.jsonl、adapter_config.json、adapter_model.safetensors、base_predictions.jsonl、adapter_predictions.jsonl、metrics.json、report.md、cost_summary.json。

数据核验日志保存规则与自动评审短理由，不在文档或仓库保存密钥。manifest 记录文件 SHA256，下载后校验。租赁实例关闭前确认产物已保存并能读取；若同一实例承载模型推理，关闭后程序会暂时无法回答，须在演示时启动服务或另行部署，不得宣称下载文件就能继续远程推理。本轮不实际租赁。

这些结果是程序外的开发与实验文件，不导入业务数据库，也不创建前台实验页。评估完成后按 [部署与接入方案](05_微调模型部署与程序接入.md)导出并部署模型，程序仅配置并调用该服务。报告固定显示“自动生成银标，未经人工法律验证”，简历表述用真实数据规模、方法和观察结果，不承诺专业正确率。

## 11. 预算执行规则

| 项目 | 规划上限 | 执行门槛 |
| --- | --- | --- |
| 在线 API/数据生成/自动评审/重排/联网 | 80 元 | 配置账户地域与单价，先 30 条成本探针，再计算余量 |
| GPU 训练＋前后评估＋短时推理服务演示 | 150 元 | 先核对实时报价，包含启动/模型下载/评估/存储费用，设置最长占用时间 |
| 预留 | 70 元 | 默认不自动消耗，确有需求才在总额不变下显式调整配置并记录 |

有效总额限制：settled＋reserved＋estimated_unsettled≤300；API 支出加预留不得超过本阶段限额。所有模型调用必须在服务端 reserve 最大输入＋最大输出的保守预估，完成后根据 usage 结算；供应商价格未知则拒绝付费批任务。预留与结算在 budget_account 单文档原子更新，ledger 用 request/run_id 对账，禁止并发检查后各自超额放行。

上述按 token 预留适用于云端收费辅助模型；自托管微调推理标记 billing=resource_time，按 GPU 租用时段纳入同一总预算，不虚构 token 单价或重复扣费。服务侧若实际按 token 收费，则必须改为对应计费模式并配置真实价格，不能沿用自托管零边际 token 费用假设。

GPU 不能由应用账本强制停止供应商计费；须在租赁平台设置到期停机/关机提醒并外部核对账单。最长租期按 floor((剩余 GPU 限额−存储/其他预估)/每小时价格)计算，另设置 6 小时绝对上限，先到者停止；关机、释放和磁盘续费分别确认，不能把脚本退出当停费。

80/150/70 是预算分配，不是市场报价或一定足够的保证。若按真实价格估算不能完成，先减少训练量/证据长度和评估轮次，保留独立测试与真实产物；仍不可行则明确阻塞，不用模拟训练填补。

价格核对入口为[百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)，实际按账户与地域保存 pricing_revision；免费额度不计作已确认可用预算，也不能依赖首次赠送额度证明成本可控。
