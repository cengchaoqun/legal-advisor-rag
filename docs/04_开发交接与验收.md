# AI 开发交接与验收

版本 V0.4。本文件是实施任务与通过条件，不是已运行的功能报告。当前仓库只有需求、设计和静态画板，下面的工程文件与命令均是后续开发必须实现的目标，不得把文档命令可见当成程序已经存在。

## 1. 开发入口与阅读顺序

先读[总纲](../掌柜智库_概要设计总纲.md)，再读 01 架构、02 契约、03 数据/训练文档，然后读取 contracts 下的 Schema/OpenAPI 与[默认参数](contracts/默认配置.json)。使用 [pen](../designs/法律咨询工作台_低保真.pen)实现统一工作台；数据与状态遵循 V0.4 契约，历史归档不是业务依据。

本项目已完成业务访谈。技术实现遇到可逆的常规选择自行决定并记录；仅在外部账户、付费资源、资料访问或硬件不可满足时报告具体阻塞。不能重新询问是否加入登录、多租户或人工审批，也不能擅自扩成综合法律产品。

## 3. 阶段任务和完成条件

以下阶段依赖顺序执行；每阶段先编写关键行为测试，再实现并验证，测试聚焦外部契约与失败语义，不以复述代码的断言代替功能验证。文档和低保真微调无需额外编写镜像测试。

### P0：环境与契约探针（目标第 1 天）

创建 pyproject、settings、领域模型、部署清单和 preflight；锁定依赖/镜像版本，不复用教学中的演示密码。检查可用内存、磁盘、Docker/WSL/Linux 网络、四库连接、模型下载和 API 可用性。

预检分离 offline 与 live：offline 不联网、不计费，验证 Schema/参数与缺失配置错误；live 明确列出将调用的模型和预估费用，检查账户单价后只运行最小请求。GPU 预检属于训练阶段，不自动租用。

通过条件：领域样例可校验；/health/live 正常；依赖缺失时 ready 返回 unready 而非全绿；live 成功才可标记已连接。CIM 等硬件读取失败时使用实际环境允许的替代或记录未知，不捏造硬件容量。

### P1：持久化任务与导入骨架（目标第 2～3 天）

实现元数据/对象存储、格式解析、任务租约、重试、同内容幂等、确定性切片。先以 1 份真实公开资料验证来源，再扩大资料量。

通过条件：重复上传不重复创建索引/调用；进程重启可从阶段产物恢复；扫描 PDF 不会以空正文成功；元数据缺失不会产生人工待审阻塞；私有附件与知识资料 scope 区分。

### P2：双索引和图证据（目标第 3～5 天）

实现 BGE-M3/Milvus 混合向量、Neo4j 节点与约束、显式引用消歧及 limited 发布。记录每次索引模型/策略版本，证据原文统一存 MongoDB。

通过条件：至少一条真实来源支持的图路径可回取原文；若资料中没有可解析关系，先寻找适当公开样例，不编造边。图构建失败而向量成功自动进入 limited；向量失败不发布新版本；重试图阶段后可升级可用性。

### P3：咨询、SSE 与统一前端（目标第 5～7 天）

实现会话、结构化事实、三条本地路径、RRF、重排、证据编号、文本流和查询快照。按 pen 五画板完成同源前端，补齐必要空/错误/中断状态。联网适配在默认关闭下可不配置，但手动开启必须给出真实结果或明确 unavailable。

本阶段先通过可独立执行的契约、真实检索和明确标识的离线生成替身测试：可点击来源定位正文；条件不足能澄清；没有证据不强答；SSE 断线重放不重复文字、不重复模型调用；同一编号不跨 query 串线。替身仅用于测试，APP_MODE=live 不允许使用。

依赖说明：唯一允许的真实回答服务到 P5 才完成微调部署；因此 P3 此时标记“链路完成、真实回答待 P5 补验”。P5 接入后补验三个场景各一轮真实问答与追问，P6 前必须完成。不能用辅助云模型代答或声称 P3 已完成真实问答验收；P4 数据生成不依赖该回答服务。

### P4：真实资料与自动数据（目标第 7～9 天）

完成有记录的来源采集、银标样本生成、源组划分与自动质检。先 30 条成本探针，再按预算扩到默认 300/60/90。未达到数量时保存实际分母和原因，不能用空白或近重复样本占位。

通过条件：来源均可回溯、同案/同源组不跨 split，五项能力均覆盖，测试答案未被导入知识库，数据质检和支出有记录。

### P5：程序外微调、部署与接入（目标第 9～12 天）

先核对 GPU 价格及停止条件，再运行 10 步探针、真实 LoRA 和固定测试集前后推理。保存并校验产物，合并导出后部署推理服务，配置到程序的回答模型适配器；不创建实验前台。训练失败不得伪造 checkpoint；预算不够时明确记录，不将 mock 当真实实验。

通过条件：适配器可加载、基础/LoRA 使用相同基础模型快照和证据配置、预测文件存在、自动指标真实可重算、报告明确银标与自动评审限制；模型不必提升才算完成实验，但必须完成程序接入；至少一次真实咨询回答的调用记录与部署清单匹配。

### P6：消融、故障演示与交接（目标第 12～14 天）

固定测试集对比检索路线，完成已确认场景与异常的演示脚本、依赖清单、启动文档和报告。尚未完成项目明确标记，不能用“设计已包含”作为实现验收。

时间为工作排序目标，不承诺固定人力下必然完成；遇到外部阻塞优先完成本地闭环并记录影响，未经确认不增加工期目标之外的功能。

## 5. 开发后必须提供的命令契约

下列是目标入口，开发者必须实现脚本参数并验证，当前文档本身不创建脚本。PowerShell 工作目录均为项目根目录。

```powershell
Set-Location 'C:\Projects\legal-advisor-rag'
uv sync
uv run python -X utf8 scripts/preflight.py --mode offline
docker compose -f deploy/compose.yml up -d
uv run python -X utf8 scripts/preflight.py --mode live
uv run uvicorn legal_rag.api.main:app --host 127.0.0.1 --port 8000
```

worker 在另一个终端执行 `uv run python -X utf8 -m legal_rag.worker.main`。根 pyproject 使用 src 布局并配置可安装包，不依赖临时 PYTHONPATH。浏览器统一打开 8000，无第二个 import/query 客户端。

```powershell
uv run python -X utf8 scripts/collect_sources.py --manifest data/manifests/sources.jsonl --limit 24
uv run python -X utf8 scripts/import_seed.py --manifest data/manifests/sources.jsonl
uv run python -X utf8 scripts/build_dataset.py --config docs/contracts/默认配置.json --pilot 30
uv run pytest tests/unit tests/contracts -q
uv run pytest tests/integration -q
uv run python -X utf8 scripts/evaluate_retrieval.py --split test --web off
```

GPU Linux 环境另装 training 依赖组，再运行以下目标入口；不复制含真实密钥的本地配置到公共仓库。

```bash
uv sync --group training
uv run --group training python -m training.train_lora --config docs/contracts/默认配置.json --smoke-steps 10
uv run --group training python -m training.train_lora --config docs/contracts/默认配置.json --run-id <实际实验ID>
uv run --group training python -m training.predict --run-id <实际实验ID> --variant base
uv run --group training python -m training.predict --run-id <实际实验ID> --variant adapter
uv run --group training python -m training.evaluate --run-id <实际实验ID>
```

正式 run 不能直接重用 smoke 的临时样本或将其步数冒充完整训练。评估文件保存在程序外；新增 `training.merge_export` 导出模型，再按 [部署接入](05_微调模型部署与程序接入.md)启动推理服务，并运行 `scripts/verify_model_connection.py` 核对模型、流式输出和一次真实 RAG 回答。

## 6. 配置与秘密

.env.example 字段至少包含 APP_MODE、MONGO_URI、MILVUS_URI、NEO4J_URI/USER/PASSWORD、MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY、LLM_BASE_URL/API_KEY/MODEL（微调后的回答服务）、MODEL_DEPLOYMENT_MANIFEST、AUX_LLM_BASE_URL/API_KEY/MODEL（辅助抽取/HyDE）、RERANK_BASE_URL/API_KEY/MODEL、MCP_URL/API_KEY、EMBED_MODEL_REVISION、PRICING_FILE。所有密钥为空或占位，不输出真实值。

非秘密参数来自默认配置，价格独立文件包含 vendor、region、model、input/output 或调用单价、有效日期和账单核对时间。API 就绪检测不打印 token。配置缺失的联网只标 unavailable，不能影响默认 web=false 的咨询。

## 7. 验收演示脚本

1. 展示来源清单和实际文档数量，进入统一资料页导入一份真实文件；查看元数据未知和 limited 标记。
2. 对三个场景各问一个有依据的问题；展示一条需要澄清和一条依据不足的问题。
3. 打开引用原文、页码/条款与版本；在知识关联页展示真实来源支持的案例引用路径。
4. 关闭图服务或注入超时，展示降级提示；恢复后重试，无重复切片或关系。
5. 断开 SSE 并重连，展示不会重复输出；查看历史与证据快照。
6. 在程序外展示真实 LoRA 产物和评估文件，再在咨询页面执行一次由已部署微调模型回答的真实问题；调用记录核对模型及产物摘要，前台无训练菜单。
7. 展示检索消融和实际成本账本，说明未实现项、外部依赖和预算余量。

## 8. 可直接交给下一位 AI 的任务说明

完整可复制任务说明见[设计复核与开工提示词](06_设计复核与开工提示词.md)。先读总纲 V0.4、docs/01～06、contracts 和 designs，再按 P0→P6 实施；每阶段通过后继续推进。P3 的真实三场景问答待 P5 部署接入后补验；开发目标仍是本机单人真实演示，不以 mock 冒充外部依赖连通、资料或训练完成。

设计已足以开始编码和环境验证；真实资料可获取性、价格、账户、硬件及训练结果依然要靠实际执行取得证据。
