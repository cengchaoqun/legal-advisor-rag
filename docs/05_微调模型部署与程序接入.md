# 微调模型部署与程序接入

版本 V0.4，2026-10-21。按用户纠正：先在程序外把模型训练好，再部署并接入程序。训练、数据生成、实验报告与模型发布管理均不进入前台。本文是设计及后续执行入口，目前没有真实模型或推理服务已部署。

2026-10-21 更新：回答基座改为Qwen3-8B，SFT+LoRA、单卡24GB，训练/预测/在线请求固定非思考模式。新增MODEL_TOKENIZER_PATH及服务器逐文件核验启动；完整步骤见[Qwen3操作手册](08_Qwen3-8B微调与接入操作.md)。

## 1. 最终关系

```text
程序外：准备数据 → SFT/LoRA 微调 → 自动评估 → 合并并导出模型
                                             ↓
                                   独立推理服务（部署一次）
                                             ↑
浏览器咨询 → 业务后端 → 检索 / 图检索 / 精排 → 编号证据
                                             ↓
                         调用训练好的模型 → 流式答案 → 浏览器
```

程序只消费推理接口，不启动训练，不生成训练任务，也不为前台提供实验/报告接口。训练代码可保留在仓库独立 training 目录，但它不属于应用运行生命周期；普通启动命令不会导入训练模块、加载训练依赖或租用 GPU。

## 2. 模型角色分离

| 用途 | 默认实现 | 调用配置 |
| --- | --- | --- |
| 咨询最终答案 | 已微调的 Qwen3-8B；服务别名 legal-labor-sft-v1 | LLM_BASE_URL / LLM_API_KEY / LLM_MODEL |
| 法律要素/元数据提取、HyDE | 辅助云端 qwen-flash | AUX_LLM_BASE_URL / AUX_LLM_API_KEY / AUX_LLM_MODEL |
| 重排序 | qwen3-rerank | 独立 RERANK 配置 |
| 向量化 | BGE-M3 | 固定模型快照，与导入一致 |

“最终答案”和“辅助生成”必须是两个明确的客户端实例，不能因旧代码变量都叫 llm 就共用同一个默认地址。为证实接入，实际咨询查询保存 generation_model_id 与 generation_artifact_sha256；生成前失败则不宣称已经使用微调模型。

模型服务不可用返回 MODEL_SERVICE_UNAVAILABLE，向用户显示稍后再试；禁止静默退回 qwen-flash 并继续声称使用微调模型。原始辅助云模型不接管最终回答。若日后需要回滚，维护者修改配置并记录实际模型版本，前台不提供切换按钮。

## 3. 程序外产物

先执行 docs/03 中的真实训练和同模型前后比较，保留 LoRA 适配器、数据/训练版本和评估文件。首期默认将适配器与准确的基础模型快照合并，导出 merged_model 目录，包含权重、config、tokenizer 和 chat_template 所需文件。

合并使用 PEFT 的 merge_and_unload 语义，再保存完整权重和 tokenizer；不能只把 adapter_model.safetensors 当作完整模型目录部署。合并前后各跑一组固定输入，核对 tokenizer、解码和输出差异；量化前后如再有转换，须另记产物版本和验证。

后续需实现的独立命令入口：

```bash
uv run --group training python -m training.merge_export --run-id <实际训练ID> --output-dir artifacts/<实际训练ID>/merged_model
```

该命令当前是开发目标，不代表脚本或模型已经存在。输出 deployment_manifest.json，包含基础模型 revision、适配器摘要、完整模型文件清单及摘要、tokenizer/chat_template 摘要、服务别名、上下文长度和评估记录位置。目录摘要按“相对路径排序＋逐文件 SHA256”计算，不使用不可核验的手填标签。

模型别名相同不代表权重相同：GET /v1/models 只能核验接口公布的名称，还须核对部署清单、服务启动目录和文件摘要。后端日志保存配置清单摘要及服务模型名；不能把一个返回任意同名字符串的 mock 当作真实接入。

## 4. 独立推理服务

默认在兼容的 Linux GPU 环境通过 vLLM 部署完整合并模型，提供 OpenAI 兼容 Chat Completions。版本及硬件兼容性在部署探针中验证；vLLM 不作为 Windows 业务 API 进程的内嵌依赖。

以下为部署目标命令，路径对应上一步实际产物；密钥由用户注入环境，不写入仓库：

```bash
vllm serve ./artifacts/<实际训练ID>/merged_model \
  --host 127.0.0.1 \
  --port 8008 \
  --served-model-name legal-labor-sft-v1 \
  --max-model-len 1536 \
  --api-key "$MODEL_SERVICE_API_KEY"
```

若业务程序与模型服务不同机器，可通过受控网络或 SSH 本地转发连接，再把本地转发地址配置给后端。不要为方便演示直接把无鉴权推理端口暴露到公网。服务启动、端口可达和模型实际回答是三项不同检查。

上面的服务命令和客户端兼容行为依据 [vLLM 官方 OpenAI 兼容服务文档](https://docs.vllm.ai/en/stable/serving/online_serving/openai_compatible_server/)。密钥、租赁和网络配置本轮均未执行。

## 5. 程序接入配置

只修改后端环境配置，不在前台增加页面：

```properties
# 示例地址；实际部署在另一机器时使用其受控地址或本地转发端口
LLM_BASE_URL=http://127.0.0.1:8008/v1
LLM_MODEL=legal-labor-sft-v1
LLM_API_KEY=<由用户注入，与推理服务一致>
MODEL_DEPLOYMENT_MANIFEST=<已核对的deployment_manifest.json路径>

# 辅助模型保留独立配置；真实值不提交Git
AUX_LLM_MODEL=qwen-flash
AUX_LLM_BASE_URL=<辅助云服务地址>
AUX_LLM_API_KEY=<辅助云服务密钥>
```

generate 节点将“范围、用户事实、编号证据、输出规则”组为 messages，调用配置模型的 chat.completions，stream=true；后端把已持久化的增量转换为原有业务 SSE。浏览器不直接访问模型服务或获取 API 密钥。

默认服务总上下文 1536 tokens，在线输入最多 1024、输出最多 512；必须按导出 tokenizer 对完整 messages 计数，包含模板开销。优先减少不相关证据和历史冗余，保留必要事实/例外；仍超过则提示输入过长或依据无法完整容纳，不静默裁掉条件。候选证据字符上限只是初筛，不能替代 token 计数。

如实际模型/资源支持更大上下文，可在验证后同步修改配置与部署清单；不能仅修改前端字符限制假装模型支持。微调训练长度与部署支持长度分别记录，超训练长度效果须单独观察。

## 6. 接入通过条件

后续实现 scripts/verify_model_connection.py，运行时检查：

1. 配置完整、模型清单存在、权重/tokenizer 摘要匹配；不打印密钥。
2. GET /v1/models 包含明确的 LLM_MODEL，模型 ID 不随意选择列表第一项。
3. 一次普通回答和一次流式回答可完成，支持 system/user messages 与预期 chat_template。
4. 一次真实 RAG 查询从 MongoDB/Milvus/Neo4j 取证据，并由该模型生成答案；保存实际模型标识、清单摘要、引用结果和调用日志。
5. 停止模型服务后得到明确错误，不调用辅助云模型冒充回答；恢复服务后无需前台更改即可继续使用。
6. 业务前台和 OpenAPI 中均无训练/实验/报告管理入口；独立评估文件仍可用于开发者解释结果。

基础模型与 LoRA 对比属于程序外自动评估，真实接入检查属于应用验收，两者都保留，不能以离线预测成功替代在线咨询接入成功。

## 7. 预算与运行边界

原 300 元上限继续有效，GPU 150 元阶段额度现在同时覆盖训练、评估、合并和短时部署演示；不是额外赠加一笔部署费用。API 80 元用于辅助模型、重排和数据生成/自动评审，70 元默认预留。

自托管推理按机器占用计费，不能按云模型 token 单价重复计算；token 仍记录以分析输入规模。租赁账单包含服务空闲、磁盘等费用，须核对停止/释放条件。程序外服务停止后回答功能会暂时不可用，应用本身不会重新训练或自动租一台机器。

不把 300 元理解为永久在线部署费用。若预算与硬件探针证明当前方案不可运行，记录具体限制并收敛模型规模或部署方式；不得省掉真实接入这一交付要求，也不未经授权增加付费资源。
